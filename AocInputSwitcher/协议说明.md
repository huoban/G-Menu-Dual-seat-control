# AOC AGON 显示器输入源切换工具 —— 协议说明（官方 RhHidAPI 通道版）

适用型号：AOC 爱攻 AG275UXM2（27″ MiniLED 4K 160Hz 双模 320Hz）。
控制方式：**经 USB 上行线**，通过显示器内部的 Realtek USB↔I2C 桥，对显示器执行标准 DDC/CI（VCP 0x60 输入源）读写。
**本版本走官方 G-Menu 同款 `RhHidAPI.dll`（MI_02 HID 接口）**，与官方软件完全一致的物理通道。

> 用途为用户自有设备的互操作（切换/查询输入源），不涉及破解、不改动固件。
>
> **为什么不用纯 WinUSB（MI_00）？** 真机 + 设备管理器 + 反编译三方证实：
> 复合设备的 MI_00 虽由 `winusb.sys` 驱动，但其友好名是 **"AGON3 AG275UXM Light FX Device"（灯效控制器）**，
> 在它上面发 DDC 事务（0xF6/0xC6/0xD6）一律 `err=31`、无任何 DDC 应答；**输入源切换的物理通道只有 MI_02 HID**。
> 官方 G-Menu 的 `AOCOper.SetSource → VCP 0x60 → RH_HidI2C* → RhHidAPI.dll → hid.dll` 即走 MI_02。

---

## 1. 真机 USB 设备拓扑

复合设备：`USB\VID_05F6&PID_AC2F`（Realtek USB-I2C 桥，序列号 `9876543210`）。

| 接口 | 驱动 | 友好名 / 用途 | 是否用于输入源 |
|---|---|---|---|
| **MI_02** | HID（HIDClass） | **DDC/CI 输入源控制通道（RH_HidI2C）** | ✅ 本工具使用 |
| MI_00 | winusb.sys（winusb.inf，匹配 `USB\MS_COMP_WINUSB`） | **"AGON Light FX Device" 灯效控制器** | ❌ 无 DDC，err=31 |
| 父设备 | usbhub | `USB\VID_05F6&PID_AC2F\9876543210` | ❌ |

MI_02 的标准 HID 设备接口路径形如：
`\\?\hid#vid_05f6&pid_ac2f&mi_02#8&9c34c41&0&0000#{4d1e55b2-f16f-11cf-88cb-001111000030}`

## 2. 官方 RhHidAPI 调用链（来自反编译）

`RhHidAPI.dll` 为 **32 位（x86）原生库**，G-Menu 自带路径 `RTKUSBSDKDriverLib\32bitrelease\RhHidAPI.dll`。
因此**控制程序必须以 x86 编译**，且 `RhHidAPI.dll` 与 exe 同目录。

官方流程（`Zeasn.Monitor.Lib` 的 `HubRTK` / `RTKRTKApi` / DDC 帧层）：

```
pDev = RH_OpenHid(dwDevInst)              // 入参是设备节点 DevInst，非零=成功
RH_HidI2CConfig(pDev, 110, 1, 0)          // 110=0x6E 从机地址；返回 0=成功
RH_HidI2CWrite(pDev, 0x51, 帧[2..], len-2) // 0 = 成功；寄存器/设备地址 0x51
Sleep(约 150ms)
读缓冲 buf[0]=0x6F
RH_HidI2CRead (pDev, 0x51, buf, 32)       // 0 = 成功；应答 buf[0..]=6E 8F ...
RH_CloseDev(pDev)
```

### 精确签名（C# P/Invoke）

| 函数 | 调用约定 | 签名 |
|---|---|---|
| RH_OpenHid | Cdecl | `IntPtr RH_OpenHid(uint dwDevInst)` |
| RH_CloseDev | Cdecl | `void RH_CloseDev(IntPtr pDev)` |
| RH_ListAllHidDev | Cdecl | `int RH_ListAllHidDev(ref IntPtr pp, ref uint count)` |
| RH_FreeDevList | Cdecl | `int RH_FreeDevList(IntPtr p)` |
| RH_HidI2CConfig | StdCall | `int RH_HidI2CConfig(IntPtr pDev, byte slave, byte memLen, byte speed)` |
| RH_HidI2CWrite | StdCall | `int RH_HidI2CWrite(IntPtr pDev, uint dwaddr, byte[] buf, ushort len)` |
| RH_HidI2CRead | StdCall | `int RH_HidI2CRead(IntPtr pDev, uint dwaddr, byte[] buf, ushort len)` |

所有 `RH_HidI2C*` 返回值 **0 = 成功**；`RH_OpenHid` 返回非零设备对象指针 = 成功，0 = 失败。

### DevInst 如何得到（关键）

真机上 `RH_ListAllHidDev` 曾返回 `rc=0, count=0`（G-Menu 却能用），故本工具**不依赖它**，
而是用 SetupAPI 自行枚举所有 present 设备节点：

- `SetupDiGetClassDevs(IntPtr.Zero, ..., DIGCF_ALLCLASSES | DIGCF_PRESENT)`
- `SetupDiEnumDeviceInfo` + `SetupDiGetDeviceInstanceId`，收集实例 ID 含 `VID_05F6&PID_AC2F` 的节点；
- 按优先级排序：`HID\...&MI_02` > `USB\...&MI_02` > 其它含 MI_02 > 任意 HID > 父设备；
- 对每个节点依次 `RH_OpenHid → RH_HidI2CConfig(110,1,0) → Get VCP 0x60 探测`，
  第一个回 `6E/8F` 的节点即锁定；失败则 `RH_CloseDev` 换下一个。

`RH_OpenHid` 内部对 DevInst 调 `CM_Get_Device_IDW` 取实例 ID、解析 VID/PID，再等待并打开对应 HID，
所以传入 HID 子节点或 USB 子接口节点均可（只要求实例 ID 含 VID_/PID_）。

### REA + Ghidra 原生反汇编验证（2026-10-14）

用 REA v6.5.0 + Ghidra 12.1.4 对官方 `RhHidAPI.dll` 做了完整反汇编，证实上述协议与原生实现逐字节一致：

- 本工具自带的 `RhHidAPI.dll` 与 G-Menu 内置（`resources\bin\RTKUSBSDKDriverLib\32bitrelease\RhHidAPI.dll`）**SHA256 完全相同**，字节级同一文件。
- 导出函数共 16 项，关键地址：`RH_HidI2CConfig`@0x100191a0、`RH_HidI2CWrite`@0x10019280、`RH_HidI2CRead`@0x10019350、`RH_OpenHid`@0x10018b50。
- `RhHidAPI.dll` 为**薄封装**：仅做参数校验（写 wLen≤0x80、读 wLen≤0xC0；Config 要求 slave≠0、speed≤2、memLen≤4）后虚调用设备对象 vtable（0x9c=Config / 0xa0=Write / 0xa4=Read），**不拼 DDC 字节**，payload 原样透传。
- 导出表中**不存在** `RH_HidI2CWriteS`——它是 .NET 侧（`RTKRTKApi`）的 managed 包装方法（加 `6E 51` 前缀后调 `RH_HidI2CWrite`）。

详细反汇编记录见工作目录根 `..\G-Menu_反汇编总结.md`。

## 3. DDC/CI 应用层（VCP 0x60 输入源）

完整软件帧（XOR 校验），首两字节为 `slave=0x6E reg=0x51`：

- 切换（Set VCP）：`6E 51 84 03 60 <Hi> <Lo> <CHK>`
- 查询（Get VCP）：`6E 51 82 01 60 <CHK>`
- 校验：`CHK = 帧首到校验字节前所有字节逐字节异或`。

`RH_HidI2CWrite` 下发的是**完整帧去掉前 2 字节（6E 51）**后的 payload（寻址已由 slave/寄存器参数承载）。

| 操作 | 完整帧 | 实际下发（去前 2 字节，dwaddr=0x51） |
|---|---|---|
| HDMI1 (0x11) | `6E 51 84 03 60 00 11 C9` | `84 03 60 00 11 C9` |
| HDMI2 (0x12) | `6E 51 84 03 60 00 12 CA` | `84 03 60 00 12 CA` |
| DP1 (0x0F) | `6E 51 84 03 60 00 0F D7` | `84 03 60 00 0F D7` |
| DP2 (0x10) | `6E 51 84 03 60 00 10 C8` | `84 03 60 00 10 C8` |
| 查询 | `6E 51 82 01 60 DC` | `82 01 60 DC` |

输入源编码（标准 DDC/CI）：DP1=`0x0F`、DP2=`0x10`、HDMI1=`0x11`、HDMI2=`0x12`（USB-C1=`0x15`、USB-C2=`0x16`）。

读时序：写后 `Sleep(150ms)`；读缓冲 32 字节、读前 `buf[0]=0x6F`；外层最多重试 3 次。

查询应答（Get VCP Feature Reply）标准布局：

```
6E 8F 60 [result] [type] [maxH][maxL] [valH][valL] [chk]
                            └─ max ─┘   └─ value ─┘
```

程序在缓冲前 16 字节扫描 `6E + (第2字节 bit7=1)` 的帧头；value 在帧头 +7/+8、max 在 +5/+6；并兼容旧设备 `idx=buf[1]-0x80` 的动态偏移。

## 4. 编译与运行

`RhHidAPI.dll` 为 32 位原生库，**只能 x86 编译**：

```
C:\Windows\Microsoft.NET\Framework\v4.0.30319\csc.exe /platform:x86 /out:AocInputSwitcher.exe Program.cs
```

发布文件：

- `AocInputSwitcher.exe`（x86）
- `RhHidAPI.dll`（**必须与 exe 同目录**）
- `Program.cs`（源码）

运行：

- 交互菜单：`AocInputSwitcher.exe`
- 诊断（强烈建议先跑）：`AocInputSwitcher.exe diag`
- 命令行：`AocInputSwitcher.exe hdmi1 | hdmi2 | dp1 | dp2 | query | diag`
- **离线命令（无需连接显示器、不加载 RhHidAPI.dll，任意位数进程均可运行）：**
  - `AocInputSwitcher.exe test` — 协议离线自检：构建全部 5 个 DDC/CI 帧（查询 + DP1/DP2/HDMI1/HDMI2），重算 XOR 校验并与官方帧逐字节比对，全通过即证明协议逻辑正确。
  - `AocInputSwitcher.exe list` — 本机 USB/HID 设备枚举（SetupAPI）：高亮显示 VID_05F6/PID_AC2F 目标桥是否存在，用于确认"USB 上行线是否已连接本机"。

前提：

1. 显示器 USB 上行线已连接到**本机**，并在接显示器的这台电脑运行。
2. 设备管理器中 MI_02 为 HID 设备（G-Menu 安装后自带，真机已满足）。
3. **完全退出 G-Menu（含后台托盘进程）**，避免占用；必要时右键“以管理员身份运行”。

## 5. 诊断输出与排查

`diag` 会依次打印：

1. 官方 `RH_ListAllHidDev` 的 rc/count（仅作参考，count=0 不影响后续）；
2. SetupAPI 自枚举到的全部 VID/PID 节点（DevInst、实例 ID、优先级分数）；
3. 每个节点的 `RH_OpenHid` 句柄、`RH_HidI2CConfig` 返回码、`RH_HidI2CWrite/Read` 返回码与 32 字节原始应答；
4. 锁定后再发一次查询验证读写链路。

排查要点：

| 现象 | 说明 / 处理 |
|---|---|
| 0 个设备节点 | USB 上行线未连本机 / 未在接显示器的电脑运行 |
| RH_OpenHid 返回 NULL | 该 DevInst 不是可打开的 HID；程序会自动换下一个节点 |
| Config 返回非 0 | 该节点不是显示器 DDC 从设备（Unknow Dev）；自动跳过 |
| Write/Read 非 0 或无 6E/8F | 通道可达但无 DDC 应答；退出 G-Menu 托盘 / 管理员运行后重试 |
| 加载 DLL 异常（BadImageFormat） | 用了 64 位进程；请用 x86 编译的 exe |
| 占用 / 拒绝访问 | 退出 G-Menu 托盘进程，或右键“以管理员身份运行” |
| 开发机无显示器，想验证程序本身 | 运行 `test`（协议离线自检）和 `list`（USB 设备枚举），两者均不加载 RhHidAPI.dll、无需显示器 |

请把 `diag` 整段输出（尤其每个 DevInst 的 Open/Config/Read 返回码与 32 字节原始数据）反馈。

## 6. 已证伪的路线（记录在案，避免重复）

- **纯 WinUSB（MI_00）切输入源**：MI_00 实为 Light FX 灯效控制器；`WinUsb_Initialize` 需 OVERLAPPED 才能成功，但 0xF6 配置返回 `err=31`、0xC6/0xD6 无 DDC 应答，遍历物理/关联接口均无效。
- **纯 hid.dll 直开 MI_02 标准路径**：`CreateFile` 曾返回 `err=2 (FILE_NOT_FOUND)`；官方正是在 hid.dll 之外再封装了 RhHidAPI 的枚举/打开逻辑，故改用官方库。
